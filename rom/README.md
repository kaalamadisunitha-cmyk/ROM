# 16×8 ROM Design Using Verilog HDL

## Overview

This project implements a **16×8 Read-Only Memory (ROM)** using Verilog HDL.

The ROM contains 16 memory locations, with each location storing an 8-bit data value. A 4-bit address is used to select one of the 16 memory locations.

The project includes the Verilog design, testbench, simulation waveform, and documentation.

## Features

* 16 memory locations
* 8-bit data width
* 4-bit address width
* Combinational read operation
* Verilog HDL implementation
* Testbench for all memory locations
* VCD waveform generation
* Compatible with Icarus Verilog and GTKWave

## ROM Architecture

The ROM consists of:

* A 4-bit address input
* Sixteen 8-bit memory locations
* An 8-bit data output

The address selects one memory location and the corresponding stored value appears at the output.

## Simulation

### Requirements

The following tools can be used:

* Icarus Verilog
* GTKWave
* Git/GitHub

### Compile the Design

From the project root directory:

```bash
iverilog -o rom_sim src/rom.v testbench/rom_tb.v
```

### Run the Simulation

```bash
vvp rom_sim
```

The testbench displays the ROM address and corresponding data in the terminal.

### View the Waveform

```bash
gtkwave waveform.vcd
```

Add `address` and `data` to the waveform viewer to observe the ROM operation.

## Expected Result

The simulation should show that every address correctly selects its predefined 8-bit data value.

For example:

```text
Address 0x0 → Data 0xA5
Address 0x1 → Data 0x3C
Address 0x2 → Data 0x7F
...
Address 0xF → Data 0xCA
```

## Testbench

The testbench automatically tests all 16 addresses.

For each address:

1. An address is applied to the ROM.
2. The simulation waits for the output to settle.
3. The ROM data is displayed.
4. The next address is applied.

A VCD file is also generated for waveform analysis.

## Applications of ROM

ROM is commonly used for:

* Firmware storage
* Lookup tables
* Microcontroller programs
* Character generators
* FPGA configuration data
* Constant data storage
* Digital system control

## Advantages

* Data is retained without continuous write operations.
* ROM is useful for storing fixed data.
* Read operation is simple and fast.
* It can be implemented efficiently in digital systems.

## Limitations

* Traditional ROM contents cannot normally be changed during normal operation.
* The stored data must be defined during manufacturing, programming, or FPGA configuration depending on the ROM technology.

## Conclusion

This project demonstrates the design and simulation of a **16×8 ROM using Verilog HDL**. The testbench verifies all 16 memory locations, and the generated waveform provides a visual representation of the ROM read operation.

The project provides a basic understanding of memory modeling, address decoding, Verilog HDL, testbench development, and digital simulation.
